# Controlled ablation — isolating the pass-3/4 regression

Amy's call: stop touching the corpus, vary training instead. The symptom to
isolate: classic gate climbing (17→18→19/23 across passes 2-4), robust gate
flat (8→9→9/23), benign-control inversions climbing (1→3→4), and
`cargo build`'s live score getting WORSE (0.828→0.931→0.955) across passes
2-4 despite being correctly relabeled `situation-normal` in pass 4's data.

Four runs, each from the SAME `.models/LFM2.5-Encoder-350M` base (never
chained from a prior checkpoint), reproducible with the commands below.
Score files: `ablation_expA/B/C/D.json`, plus every epoch of C individually
(`ablation_expC-e1..e6.json`).

## The four runs

- **A — class-weighted loss.** Current 815-row corpus (train 694, 52.6% dc).
  `--class-weight inverse_freq` (informative=1.807, situation-normal=1.151,
  data-critical=0.634), otherwise pass 4's exact recipe.
  ```
  .venv-train/bin/python training/finetune_sequence_classifier.py \
    --train training/v9/train.jsonl --val training/v9/val.jsonl \
    --base .models/LFM2.5-Encoder-350M --out .models/kube_ordinal_v9_expA \

    --label-order informative,situation-normal,data-critical \
    --class-weight inverse_freq
  ```

  ```
    --train training/v9/train.jsonl --val training/v9/val.jsonl \
  ```

## Verdict — contributing factors, not one root cause

**1. Repeated-epoch overfitting is the dominant, cleanest mechanism.**
Within experiment C's SINGLE training run — same data, same recipe, no
relabeling between epochs — `flag01` falls monotonically 0.527→0.156 while
`cargo build` climbs monotonically 0.633→0.955, purely as a function of
more epochs on the same 694 rows. **The delta-margin gate is perfectly
FLAT at 9/23 across all six epochs** — genuine robust separation stops
improving after epoch 1; every epoch past that is trading benign-side
calibration for classic-gate score, not learning anything the honest
metric credits. This is the single most legible result in the whole
ablation.

**2. Class imbalance is real and independently helps, but isn't the whole
story.** A (inverse-frequency weighting) produced the best benign-inversion
count of any full 6-epoch run (2) and the healthiest `flag01` (0.401) of
any v9 pass, while matching pass 4's classic/robust gate numbers exactly —
a genuine, close-to-free win. It didn't reach zero inversions, so skew
alone doesn't explain everything.

**3. Learning rate matters more than any other single lever tested.** D (lr
1e-5) produced the best classic (21/23) AND best robust (11/23) gate scores
of the entire investigation — better than every one of the four original
passes. Still 3 benign inversions, so an improvement, not a fix.

**4. Run-to-run noise is real and non-trivial — a caveat on reading the
passN sequence as a clean trend.** B was built to exactly reproduce pass
3's result (identical corpus, identical recipe, identical seed) and did
NOT: 16/23 classic vs pass 3's 18/23, 10/23 robust vs pass 3's 9/23. This
training setup is not bit-reproducible run-to-run on this GPU (no
`torch.use_deterministic_algorithms`, no fixed cuBLAS workspace — not
chased further this round). Some fraction of the apparent pass 2→3→4
trend sits inside this noise band. It does NOT undermine finding #1, which
is a within-run signal immune to across-run noise — but it means don't
over-read the passN sequence as a precise monotone line.

**Is any of A-D closer to a rollout candidate than pass 4?** Closer, not
close. D wins on both gate metrics outright. A wins on the specific
benign-control symptom this whole investigation was chasing. Neither
clears a majority of gating constraints under the honest metric (9-11/23
of 23), and both still show real benign-control inversions on a probe set
of only four rows. **None of A-D replaces `kube_ordinal_v9`** — this was a
diagnostic round, and nothing here changed `.models/kube_ordinal_v9`
(pass 4's export is untouched; A/B/C/D exported to separate
`kube_ordinal_v9_exp{A,B,C,D}[-eN]` directories, all gitignored, disposable).

**What I'd try next:** combine D's LR with A's weighting in one run, and
watch it epoch-by-epoch the way C did — the prediction from finding #1 is
that the same flag01/cargo-build convergence should still appear, just
slower, so the real fix is probably "fewer epochs" (the robust gate is
already flat by epoch 1) combined with the weighting and LR wins, not any
one of the four alone.
