### Reasoning

1. **Read-only / Observational commands (`informative`)**:
   - `grep -nE`, `diff`, `sort -rn`, `git show --`, `head -100`, `date`, `grep -A`, `git merge-base`, `head -35`, `grep -A -B -n`, `echo -c`, `find -type`, `head -c`, `xargs -l` (running read-only commands like `grep` or `wc`), `grep -oE`, `rg -rn`, `grep -vE`, `git rev-list`, `head -16`, `cat -A`, `find -name -path`, `tail -150`, `grep -aE`, `git log -4`, `grep -A2 -n`, `pwd`: These are standard read-only commands that observe, query, or stream data without modifying any durable state.
   - `export`: Under Rule 4, setting environment variables is ephemeral process state and is labeled `informative`.
   - `curl -H -s`: Streams data to the terminal without creating a durable artifact (Rule 2), hence `informative`.
   - `grep -n >>` and `grep -c >>`: The `>>` in the shape key is a parsing artifact of the conflict markers (`>>>>>>>`) in the search pattern. The actual execution is a read-only `grep` search, which is `informative` (Rule 8).

2. **Routine operations and state modifications (`situation-normal`)**:
   - `python3 -c >` and `bash -c`: These are interpreter carriers. Under the Pilot Rulings, a stripped-payload interpreter carrier biases up from informative because code runs, but is labeled `situation-normal` (never `undecidable` or `data-critical` on suspicion). Additionally, the `>` redirect in `python3 -c >` creates a durable file artifact (Rule 2).
   - `git add -u` and `git commit - -- -F -q`: Routine git operations. Commits create durable artifacts that are easily backed out (`git reset HEAD~1`).
   - `cargo test -- --lib -p`, `cargo run -p`, `cargo build --bin -p >`, `cargo test --lib`, `cargo +1.98 --all >`, `cargo clippy --all`, `timeout --lib` (running `cargo test`), `cargo test >`, `cargo run`, `cargo check`: Under Refined Rule 16, building, testing, linting, or running against already-resolved dependencies is `situation-normal`. Redirects (`>`) to log files are also routine file creations.
   - `rm` and `rm -f`: Under the Pilot Rulings, single-file deletion of developer files (scratch files, manifests, source files) is treated as `situation-normal` at the clause grain.
   - `gh pr >`: Performs a read-only query (`gh pr view` / `gh pr checks`) but redirects the output to a file (`>`), creating a durable artifact (Rule 2), making it `situation-normal`.
   - `git push -q`: Under the Pilot Rulings, plain `git push` (without `--force`) is `situation-normal` because publishing new commits/tags is not irreversible.
   - `rustfmt`: Formats source files in place. This is a routine developer operation on source files, easily backed out via git, hence `situation-normal`.
   - `kubectl -- -n`: Under the Pilot Rulings, verb-blind shape keys for `kubectl` bias UP to `situation-normal` (rather than `mixed` or `informative`) because the key cannot exclude mutating verbs.
